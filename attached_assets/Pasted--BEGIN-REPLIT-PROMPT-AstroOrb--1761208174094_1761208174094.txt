Цель: Реализовать модуль «Соляр» в AstroOrb:
- Пользователь выбирает год (напр. 2025/2026) и город, где будет в момент соляра.
- Бэкенд вычисляет момент соляра (точный return по долготе Солнца, с учётом таймзоны выбранной локации) и строит солярную карту.
- Альтернатива: «снимок на ту же дату» (локальная полночь или время рождения) — по выбору.
- Итог: отдаём данные карты и интерпретацию. За разные годы — списываем сферы (или бесплатно по подписке).
- Кэшируем результаты в БД, повторный запрос года не списывает повторно.

## 0) Контекст проекта
- Frontend: apps/web (React + TS), экраны NatalChart/Solar.
- Backend: apps/api (Express + TS), Prisma + Postgres, модуль астрологии `src/astrology/*`, OpenAI-промпты в `src/astrology/prompts/*`.
- Энергия: есть механизм списаний (features).

3) Бэкенд — расчёт соляра
3.1 Новый модуль эфемерид и соляра
Файл: apps/api/src/astrology/solar.ts — ПОЛНЫЙ.

Функции:

ts
Копировать код
export type SolarMethod = "exact_return" | "same_date";

export type SolarInput = {
  userId: string;
  targetYear: number;                 // напр. 2026
  method: SolarMethod;                // "exact_return" (по умолчанию) | "same_date"
  // место, где будет человек в момент соляра/снимка
  lat: number; lon: number; tzOffsetMinutes: number;
  placeLabel: string;                 // подпись места для UI
};

export type SolarResult = {
  exactMomentUTC: string;             // ISO (UTC)
  localMomentISO: string;             // ISO с учётом tzOffsetMinutes
  houseSystem: string;                // берём глобальное значение (например, Placidus)
  angles: { ASC_deg: number; MC_deg: number; DSC_deg: number; IC_deg: number; };
  house_cusps: number[];              // 12 значений (0..360)
  planets: { name:string; lon_deg:number; house_index:number; speed_deg_per_day:number }[];
  aspects: { a:string; b:string; type:"conj"|"opp"|"sq"|"tri"|"sex"; orb_deg:number }[];
  meta: {
    method: SolarMethod;
    targetYear: number;
    lat: number; lon: number; tzOffsetMinutes: number; placeLabel: string;
    zodiac_type: "tropical";
  }
};
Реализация:

Натальная долгота Солнца берётся из сохранённой NatalChart.data пользователя (λ_sun_natal).

Метод exact_return (по умолчанию):

Стартовое окно поиска: от targetYear-01-01 до targetYear-12-31.

Использовать итерационный поиск (Ньютон-Рафсон) по времени T (UTC) для решения wrapAngle(λ_sun(T) - λ_sun_natal) = 0 (в градусах).

λ_sun(T) — аппаратная геоцентрическая эклиптическая долгота Солнца (можно через astronomia или существующий модуль проекта; взять «истинное» Солнце, допуска достаточна до минут дуги).

Производную по времени аппроксимировать разностью (±30 мин).

Конверсия в локальное время для выбранного tzOffsetMinutes, но (!) расчёт всегда в UTC.

На найденный момент cast-карту: вычислить наклон эклиптики, LST, углы/дома (тот же код, что в натале), планеты/аспекты — на указанной локации пользователя (relocated solar).

Метод same_date:

Построить карту на ту же календарную дату и время рождения пользователя (или локальную полночь — использовать время рождения как базовый вариант), но с годом targetYear и локацией + timezone, которые задал пользователь.

Этот режим пометить в meta.method.

Перед возвратом:

Сохранить/прочитать кэш SolarReturn по (userId, targetYear, method, tzOffsetMin, lat, lon).

Если найден — вернуть кэш без списаний; если нет — посчитать, записать, потом списать сферы (если нет подписки).

Важное UX-поведение: если у пользователя не заполнены точные время и место рождения, вернуть 409 с кодом "NATAL_INCOMPLETE" и сообщением «Для соляра нужно точное время и место рождения».

Логика:

Проверить, что у пользователя есть NatalChart; иначе 409 NATAL_NOT_INITIALIZED.

Тело: { solarId?: string, payload?: SolarResult }

Если передан solarId — загружает из кэша.

Вызывает interpretSolar(...), возвращает JSON.

GET /astrology/solar/list?from=2024&to=2030

5) README — раздел «Соляр»
Что такое точный соляр (return к долготе Солнца) и почему он предпочтителен.

Что такое «та же дата» — упрощённый снимок, может отличаться.

Требуются: точное время рождения, локация соляра (город, где будете в день рождения), выбор года.

Стоимость: 1 сфера за новый расчёт года/локации (подписчики — бесплатно).

6) Acceptance Criteria
Пользователь может выбрать год и город; по умолчанию метод exact_return, есть опция same_date.

Бэкенд вычисляет момент соляра с точностью до минут (итерационный поиск по долготе Солнца), строит карту на выбранной локации.

Результат кэшируется; повторный запрос с теми же параметрами не списывает сферы.

Интерпретация выдаёт структуру (Солнце/Луна/угловые/соединения) и практические советы.
