Цель: Исправить и довести до продакшена оплату Telegram Stars (XTR) в Astro Orb. Устранить отмены платежей: гарантировать ответ на pre_checkout и приём successful_payment. Добавить рефанд, логи, и фронтенд-кнопку «Оплатить Stars».

Бэкенд — Stars
1) Новый модуль Telegram API
Файл: apps/api/src/payments/stars.ts (ПОЛНЫЙ)

Экспорт:

createStarsInvoice(args) — вызывает Bot API createInvoiceLink ИЛИ sendInvoice для цифровых товаров:

currency: "XTR", provider_token: "" (для digital).

prices: [{ label, amount }] — amount в минимальных единицах Stars.

payload — наш подписанный payload (userId, kind, packId/tier, nonce).

опционально start_parameter (одиноч/мульти-чат по кейсу).

answerPreCheckout(ok, error?) — обёртка над Bot API answerPreCheckoutQuery.

refundStars(telegram_payment_charge_id, amount?) — Bot API refundStarPayment.

HTTP вызовы делать через node-fetch/axios. BOT_TOKEN брать из .env.

2) Вебхук Telegram
Файл: apps/api/src/routes/telegramWebhook.ts (НОВЫЙ, ПОЛНЫЙ)

Эндпоинт: POST /webhooks/telegram/:secret

Обрабатывает три типа update:

pre_checkout_query — валидировать invoice_payload (наше HMAC). Если всё ок, вызывать answerPreCheckoutQuery({ ok: true }). Сделать это < 10 сек.

message.successful_payment — зачесть покупку:

создать/обновить Payment со status="confirmed", provider="stars", starsChargeId, amountUSD (по внутреннему курсу из price.ts), amountTON (необязательно), kind/tier/energyAmount по payload.

начислить энергию/активировать подписку.

Любой другой — логировать (pino).

Если payload невалиден — answerPreCheckoutQuery({ ok: false, error_message: "Order validation failed" }).

Важно: если бот не ответит на pre_checkout в 10 секунд, платёж будет автоматически отменён. (Это и есть ваша текущая симптоматика.) 
core.telegram.org

3) Роуты API для клиента Mini App
Файл: apps/api/src/routes/payments.ts — ДОБАВИТЬ:

POST /payments/stars/create

Тело:

ts
Копировать код
{ kind: "energy_pack" | "subscription",
  pack?: { energy: 20|50|120 },   // если pack
  tier?: "standard"|"pro"         // если подписка
}
Создаёт черновик Payment(status="pending", provider="stars").

Формирует payload { paymentId, userId, kind, pack, tier, ts }, HMAC-подпись.

Вызывает createStarsInvoice(...) и возвращает { ok:true, data:{ invoice_url } }.

GET /payments/stars/public-key (если используете верификацию подписи на клиенте) — можно опустить.

В существующем /payments/price — вернуть цену в Stars (XTR) для каждого товара (конверсия из USD по вашей таблице).
