Задача: обновить Astro Orb так, чтобы:
1) При первом входе пользователь может нажать ТОЛЬКО на «Натальная карта». UI явно указывает, куда нажать.
2) Собственная натальная карта создаётся БЕСПЛАТНО один раз и сохраняется в профиле «навсегда». Все прочие механики (соляр/гороскоп/совместимость/вопросы) используют сохранённую карту.
3) Внутри экрана натальной карты можно создать натальную карту ДРУГОГО человека (гостевую) за 1 сферу. Эти карты сохраняются в профиле пользователя (списком), их можно выбирать для совместимости и т.п.

3) Backend — роуты и сервисы
Новый сервис кеширования и извлечения натала:

Файл: apps/api/src/astrology/natalService.ts (новый)

computeNatalFromUser(user: User): NatalData — существующий расчёт (используй astrology/natal.ts), возвращает структурированные данные.

ensureUserNatalChart(userId: string): NatalChart — если у пользователя нет NatalChart, вычисляет computeNatalFromUser, создаёт запись (БЕСПЛАТНО), возвращает NatalChart. Если есть — возвращает существующую.

recomputeIfProfileChanged(userId: string) — опциональная функция: если дата/время/место рождения изменены после NatalChart.createdAt, пересчитать и перезаписать карту. Вызов при /user/update.

Маршруты:

apps/api/src/routes/astrology.ts

POST /astrology/natal/init

Требует JWT. Проверяет наличие NatalChart:

Если нет — создаёт (через ensureUserNatalChart), возвращает { ok: true, data: natalChart }. Энергию не списывает.

Если уже есть — возвращает { ok: true, data: natalChart }.

GET /astrology/natal/me

Возвращает сохранённую собственную карту { ok: true, data }. Если нет — 409 { ok: false, error: "NATAL_NOT_INITIALIZED" } (для фронтенда-гейта).

POST /astrology/natal/external

Тело (Zod):

ts
Копировать код
{
  name: string.min(1),
  gender: enum("male","female","other"),
  birthdayDate: string (ISO),
  birthTime?: string.nullish(), // "HH:mm"
  birthPlace?: string.nullish(),
  timezone?: string.default("Europe/Moscow")
}
Логика:

Списать энергию feature="natal_external" (1).

Посчитать натал по присланным данным (без записи в User), создать ExternalNatal (ownerId = текущий пользователь).

Вернуть { ok: true, data: externalNatal }.

GET /astrology/natal/external

Список гостевых карт текущего пользователя.

Все существующие маршруты /astrology/solar, /astrology/horoscope, /astrology/compatibility, /astrology/ask:

В начале обработчика: попытаться получить NatalChart пользователя. Если нет — вернуть 409 NATAL_NOT_INITIALIZED.

Для compatibility добавить опциональный вход withExternalId?: string:

Если указан — использовать данные ExternalNatal с данным id как второго участника, иначе — как раньше (ввод партнёра вручную).

Внутри расчётов использовать данные из NatalChart.data вместо пересчёта на лету (для пользователя). Для внешних — из ExternalNatal.data.

User update (необязательное, но желательно):

apps/api/src/routes/user.ts: при POST /user/update после сохранения полей рождения вызвать recomputeIfProfileChanged(userId).
