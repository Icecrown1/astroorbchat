Задача: добавить интерактивные пояснения к положениям планет в натальной карте Astro Orb. При клике по планете в визуализации открывается модальное окно с персональным объяснением вида «Солнце в Скорпионе — что это значит для тебя», с учётом знака и дома. Никаких заглушек и TODO.

## Контекст проекта
- Фронтенд: apps/web (React + Vite + TS), компонент визуализации `src/components/ChartCanvas.tsx` и экран `src/routes/NatalChart.tsx`.
- Бэкенд: apps/api (Express + TS), расчёты в `src/astrology/*`, OpenAI в `src/astrology/openai.ts`, существующие промпты в `src/astrology/prompts/*`.
- БД: Postgres/Prisma (изменений схемы нет).
- Энергия: действие «натальная карта» уже списывает энергию. Пояснения по кликнутым планетам в рамках текущей натальной сессии — **без дополнительного списания**.

## Изменить

### Backend (apps/api)

1) Новый промпт:
   - Создать файл `apps/api/src/astrology/prompts/planet.md` со следующим содержимым (полный текст, без заглушек):
     ```
     Ты — строгий прикладной астролог. На входе у тебя структура:
     {
       "profile": { "name": string, "age": number, "gender": string },
       "planet": { "name": "Sun|Moon|Mercury|Venus|Mars|Jupiter|Saturn", "sign": string, "house": number, "aspects": [{ "to": string, "type": "conjunction|sextile|square|trine|opposition", "orb_deg": number }] },
       "context": { "timezone": string, "locale": "ru" }
     }

     ЗАДАЧА: Кратко и прикладно объяснить, что значит это положение планеты ДЛЯ КОНКРЕТНОГО ЧЕЛОВЕКА.
     Формат ответа JSON:
     {
       "title": "Солнце в Скорпионе",
       "summary": "3–4 предложения по сути без воды",
       "strengths": ["пункт 1", "пункт 2", "пункт 3"],
       "risks": ["пункт 1", "пункт 2"],
       "advice": ["конкретный шаг 1", "конкретный шаг 2", "конкретный шаг 3"],
       "house_note": "1 коротная фраза, как дом модифицирует значение"
     }

     Правила:
     - Ни единой эзотерической воды, только практическая польза.
     - Если аспектов нет, поле aspects игнорируй.
     - Пиши на русском, просто и по делу.
     ```

2) Новый use-case в OpenAI-обёртке:
   - В `apps/api/src/astrology/openai.ts` добавить экспортируемую функцию `interpretPlanet(input)`, которая:
     - валидирует вход (Zod),
     - читает `prompts/planet.md`,
     - вызывает модель `gpt-4o-mini` с function-calling ОТКЛЮЧЕНЫМ (прямой JSON-парсинг по `response_format: "json_object"` или аналог),
     - возвращает строго распарсенный объект `{ title, summary, strengths, risks, advice, house_note }`.
     - При ошибке валидации/парсинга — выбрасывает HTTP 400 с понятным сообщением.

3) Новый роут:
   - В `apps/api/src/routes/astrology.ts` добавить `POST /astrology/planet`:
     - **Auth**: требуется JWT.
     - Тело запроса Zod:
       ```ts
       {
         planet: z.enum(["Sun","Moon","Mercury","Venus","Mars","Jupiter","Saturn"])
       }
       ```
     - Логика:
       - Получить пользователя из JWT (`req.user.id`).
       - По данным пользователя вычислить или получить из уже существующей функции `computeNatal(user)` положения планет, знак и дом.
       - Найти объект по `planet` и построить вход `interpretPlanet`.
       - Вызвать `interpretPlanet` и вернуть `{ ok: true, data }`.
     - **Списание энергии**: не списывать (эта операция считается детализацией уже построенной натальной карты в текущий день).
     - Обработать ошибки: 404 если планета не найдена; 429 если превышен rate limit (использовать общий middleware); 500 — общий.

4) Тесты:
   - В `apps/api/src/tests/api.spec.ts` добавить кейсы:
     - `POST /astrology/planet` c валидным JWT и `{"planet":"Sun"}` → `200`, содержит поля `title, summary, strengths, risks, advice, house_note`.
     - Невалидный `planet` → `400`.
     - Без JWT → `401`.
