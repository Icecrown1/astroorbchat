# Внутренняя сборка и выход в закрытый тест

## Спринт 2 · опубликованный сервер и сборка

В отдельном [Android Replit](https://replit.com/@admiraldasaev/AstroOrbi-Android-Sandbox) проверены маркер БД, отсутствие токена Telegram, защищённые маршруты и библиотека Swiss Ephemeris. На HTTPS создан выделенный синтетический профиль. Обмен кода прошёл один раз, повтор получил 400. Запросы профиля, магазина, статуса и истории Таро, матриц, историй совместимости, Оракула и гороскопов вернули 200. Расчёт натала вернул 12 объектов, повторное чтение карты и запрос важных дат прошли. Маршруты истории без авторизации возвращают 401. Страница возврата содержит отдельные ссылки для APK и внутренней сборки. [Статус сервера](https://astro-orbi-android-sandbox.replit.app/api/health).

Первая локальная полная сборка 0.2.4 (4) и [CI-сборка 0.2.5 (5)](https://github.com/Icecrown1/astroorbchat/actions/runs/45019802223) прошли проверку AAB. Кандидат с жалобами и выключателем рекламы — 0.2.6 (6). Package app.astroorbi.mobile подлежит сверке в Console перед первой загрузкой. У сборки собственный ключ сессии для домена API. API 36, minSdk 24. Нативные .so в пакете отсутствуют. Нужны установка и обновление на физическом устройстве, проверка через Play и, при доступности, среда с размером страницы 16 KB.

Для подписи существующий сертификат нужно сверить в Play Console → App integrity, а при первой загрузке согласовать с владельцем хранение upload key и его резервной копии. Подписать проверенный AAB можно локальным JDK 21 через jarsigner с ключом владельца. Закрытый ключ в репозиторий не добавляется. После подписи проверить файл через jarsigner и bundletool, записать SHA-256, сравнить отпечаток сертификата с Console. В ручном workflow используются GitHub Environment play-internal, Secrets PLAY_UPLOAD_KEYSTORE_BASE64, PLAY_UPLOAD_STORE_PASSWORD, PLAY_UPLOAD_KEY_PASSWORD и Variables PLAY_UPLOAD_ALIAS, PLAY_UPLOAD_CERT_SHA256, PLAY_LAST_UPLOADED_CODE. Для первого в истории приложения кода значение предыдущего равно 0 лишь после проверки в Console. Переменную обновляют после фактической загрузки. Workflow отсутствует в текущем main, поэтому первый релиз можно подписать локально. Учетная запись разработчика, допуск тестера и публикация в **Internal testing** нужны для действующей ссылки вступления.

## Спринт 3 · проверка модератором

Внутренняя реализация принимает многоразовый приватный код через обычный экран входа. На сервере используется только SHA-256 в ANDROID_REVIEW_CODE_SHA256. Оригинал — 16 криптографически случайных байтов, кодирование base64url без padding. Его место — поле с закрытыми инструкциями в Play Console → App access и согласованное хранилище владельца. Установка значения в Secrets песочницы и передача в Console ещё предстоят. Для каждого входа создаётся отдельный синтетический профиль Premium с 550 ★, одним примером Таро и одним примером ответа Оракула. Магазин этому профилю недоступен. Новая сессия не открывает вопросы других проверяющих. В локальной PostgreSQL проверены два входа, разные профили, права и история.

**English instructions for App access.** Open the Profile tab (“Профиль”). Paste the private access code supplied in this Console entry into “Тестовый код” and tap “Войти”. Open “История раскладов” for a sample Tarot reading. Open Oracle (“Оракул”) and tap “История вопросов” for a sample answer. The demo includes Premium access and does not require Telegram, a purchase, or a payment card. Signing in again opens a fresh isolated profile.

Для Оракула и Таро в сборке есть «Пожаловаться на ответ». Сервер проверяет принадлежность записи и сохраняет её тип и идентификатор в events с именем mobile_content_report. Повтор одного запроса даёт одну запись. Проводить разбор следует через авторизованного ответственного, используя указанную запись в ai_questions или tarot_readings. В журнал жалоб текст ответа не копируется. Для остальных ИИ-экранов, назначения ответственного и проверки фактического разбора приёмка открыта.

**Черновик для Data safety.** Профиль содержит имя и введённые пользователем дату, время и место рождения, сессионный идентификатор и созданную историю. ЮKassa получает адрес для чека при покупке и обрабатывает платёжные реквизиты на своей странице. APK содержит Google Mobile Ads, Advertising ID и разрешения AdServices. Состав данных внешнего SDK, реальный трафик, персонализация, сроки хранения и страны зависят от выбранного рекламного и ИИ-провайдера и требуют сверки перед декларацией. В коде рабочей версии уже есть адрес поддержки, его использование для Play подтверждает владелец. Политика, публичная форма удаления, сроки и влияние удаления на общий аккаунт требуют согласования до открытия реальных аккаунтов. Владелец также подтверждает возрастную аудиторию, IARC и права на колоду. Для шрифта Noto приложена SIL OFL. Скриншоты браузера не выдавать за снимки телефона.

## Спринт 5 · предложение для ограниченного пилота общего профиля

GitHub main на момент аудита — 807226fd8ff3d2f8452ee6cc948bc643634352d8. В его дереве нет server/mobileLogin.ts и server/mobileShop.ts. Тождество этого SHA опубликованному серверу отдельно не установлено. Первый шаг после согласования — сверить развернутую версию и наличие уже действующей выдачи кода, без передачи данных пользователя.

Если такого сервиса нет, предложено отдельно добавить владельцу пилотного профиля кнопку выдачи одноразового кода в авторизованных настройках Telegram. Затронутся только разрешённый профиль и строки его кода (хэш, срок пять минут и идентификатор). Понадобится новая таблица, только если mobile_link_codes отсутствует. На Android отдельный сервис атомарно погашает код, выпускает собственный короткий токен и читает тариф, баланс и историю только этого user_id. Для первого сравнения нужен SQL-пользователь с ограниченными правами и представлениями только для этого аккаунта. Существующий /api/user/me запускает обслуживание баланса, поэтому в пилоте только для чтения его нельзя использовать без дополнительной проверки. Платёжные права, фоновые задачи и бот-токен новому сервису для сравнения не нужны.

До изменений показать владельцу конкретный diff, миграцию и обратный сценарий в зависимости от фактической схемы. На копии *синтетической схемы* проверить восстановление и закрытие доступа. Выключение — скрыть выдачу флагом, отключить погашение, отозвать SQL-права мобильного сервиса и истечь/отозвать его сессии. Сохранить данные профиля, историю и уже существующие платёжные заказы. Сейчас согласование рабочего пилота не запрошено для внутреннего теста и операции в рабочих системах не выполнялись.

Реальные продажи ждут подтверждения магазина, территории, чеков и возвратов. На тестовом сервере ANDROID_INTERNAL_PURCHASES_DISABLED=1 закрывает новые оплаты. Обработчик подтверждений и чтение статуса остаются доступны для уже оплаченных заказов. В клиенте регион берётся у Google BillingConfig. Перед продажами требуется отдельное серверное решение для географии. [Условия Google для РФ](https://support.google.com/googleplay/android-developer/answer/11950272).

## Спринты 6–9 · приёмка

Рекламные показы в Internal управляются ANDROID_INTERNAL_TEST_ADS. Значение 1 разрешает тестовые блоки Google пользователям бесплатного тарифа. По умолчанию доступ к дополнительным материалам можно открыть без просмотра. Оплата, старт и ввод профиля не вызывают межстраничное объявление. Доходная реклама ждёт договора владельца, аккаунта сети, согласий и модерации. Для платных профилей тестовые показы не включаются. Проверка SDK на телефоне и РСЯ остаются открыты.

В тестовом API генерацию новых ИИ-текстов включает только отдельный ANDROID_INTERNAL_OPENAI_KEY. В опубликованной среде при проверке генерация выключена. Перед подключением требуется подтверждение стоимости и допустимых данных. Гостевой расклад с встроенными текстами и расчёт натальной карты проверены независимо.

| Где | Результат |
|---|---|
| Браузер, веб-ресурсы AAB | Главная, бесплатная карта дня, трактовка, полноэкранный просмотр с названием. |
| Реальный Android владельца | Ранее — вход в отдельный sandbox APK. Физические проверки кандидата, обновление и возврат из внешнего браузера ещё впереди. |
| Google Play | Регистрация владельца, загрузка AAB, App access, ссылка вступления, присоединение тестировщиков, Pre-launch report и витальные показатели ожидают доступа. |
| Публичный выпуск | Перед отправкой Production нужна явная команда владельца для конкретной сборки, страны, режима покупок и рекламы. Мониторинг первых семи дней начинается после публикации. |
